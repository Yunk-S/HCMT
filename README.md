# HCMT: Hierarchical Clinical-Markov Transformer

HCMT is a continuous-time transformer for sparse perioperative clinical event trajectories. This repository contains only the training runtime: event construction, sequence datasets, sampling, model code, and training entry points. Patient data, checkpoints, external-validation artifacts, baselines, reports, and historical code are intentionally excluded.

## Overview

Each patient episode is represented as an irregular event sequence:

$$
\mathcal{S}_p = \{(x_i, t_i, v_i, q_i, f_i)\}_{i=1}^{n_p},
$$

where:

- $x_i$ is an event or context token;
- $t_i$ is the time in minutes from the episode origin;
- $v_i$ is an optional continuous measurement;
- $q_i$ identifies the token kind and observation state;
- $f_i$ is the clinical event family.

The preprocessing pipeline emits only time-supported clinical events. Stable periods are represented explicitly with clock/no-event tokens rather than fabricated five-minute-grid outcomes.

The model keeps a short-term context of up to 256 tokens and can add phase-summary tokens for pre-op, induction, surgery, emergence, PACU, and ICU phases. Each token representation can combine:

- token, event-family, token-kind, and static-patient embeddings;
- absolute time, adjacent time gap, and pairwise relative-time attention bias;
- measurement intensity and time since the last measurement;
- phase-summary embeddings and optional continuous values.

Concurrent events with the same timestamp are handled by a block-causal mask. Different tokens in the same time block cannot attend to one another, preventing leakage caused by arbitrary file or token ordering. Earlier time blocks remain causally visible.

## Prediction heads and objective

HCMT jointly predicts the next exact event/severity, its semantic family, and the waiting time:

$$
\hat{p}(e_{i+1}\mid h_i), \qquad
\hat{p}(f_{i+1}\mid h_i), \qquad
\hat{\mu}_{i+1},\hat{\log\sigma}_{i+1}.
$$

The time head is conditioned on the event family, because different clinical events have different time scales. Waiting time is modeled with a log-normal likelihood, with right-censoring support for episodes without a subsequent event.

The training objective is:

$$
\mathcal{L} = \mathcal{L}_{\mathrm{event}}
 + \lambda_f\mathcal{L}_{\mathrm{family}}
 + \lambda_t\mathcal{L}_{\mathrm{time}}
 + \lambda_{traj}\mathcal{L}_{\mathrm{trajectory}}
 + \lambda_m\mathcal{L}_{\mathrm{masked\text{-}event}}
 + \lambda_v\mathcal{L}_{\mathrm{masked\text{-}value}}.
$$

The masked-value task reconstructs observed continuous measurements such as MAP, hemoglobin, lactate, and SpO2 when values are available. It does not convert unchanged normal measurements into event labels.

## Main design contributions

1. No arbitrary 100-event cap. Eligible outcomes are selected using timestamp reliability, clinical separability, at least 100 occurrences, and at least 50 independent patients.
2. Same-time block-causal masking to prevent concurrent-event ordering leakage.
3. A hierarchical event head for exact event/severity and semantic family prediction.
4. Clock/no-event tokens and phase-summary tokens for stable periods and long-term perioperative context.
5. Relative-time attention bias, event-conditioned time prediction, and measurement-intensity context.
6. Dynamic random windows with random starts and context truncation.
7. Patient-level validation, validation-based checkpoint selection, early stopping, learning-rate plateau decay, and model/vocabulary ablations.

## Input contract

The training directory must be generated by the event preprocessor and contain at least:

```text
event_sequence_meta.json
admissions.csv
sequence_ptr.npy
token_id.bin
token_kind.bin
outcome_class.bin
time_min.bin
value.bin
has_value.bin
static_baseline.npy
token_vocabulary.json
```

The raw training source is converted with `scripts/preprocess_event_sequences.py`. MIMIC and MOVER are external-validation sources and must never be used to build the training vocabulary.

## Quick start

```bash
python3 scripts/preprocess_event_sequences.py \
  --input /path/to/train_data \
  --output /path/to/perioperative_event_sequences_v5_full
```

```bash
python3 scripts/train.py \
  --data_dir /path/to/perioperative_event_sequences_v5_full \
  --output_dir outputs/event_hcmt_v5_full \
  --epochs 1000 \
  --block_size 256 \
  --same_time_block_causal \
  --relative_time_attention \
  --event_conditioned_time_head \
  --phase_memory \
  --observation_intensity \
  --dynamic_windows \
  --early_stopping_patience 25 \
  --min_lr 1e-6
```

`best_model.pt` is selected using independent patient-level validation loss. `checkpoint_latest.pt` is used for resuming. Training outputs include `run_config.json`, `validation_history.jsonl`, checkpoints, and logs.

## Repository layout

```text
hcmt/
  data/       Event ontology, extraction, sequence datasets, sampling
  models/     HCMT architecture and task losses
scripts/
  train.py                        Main training entry point
  preprocess_event_sequences.py   Event-sequence construction
  run_ablation_matrix.py          Model-size and vocabulary orchestration
  monitor_progress.py             Log and progress inspection
```

External validation, baseline comparison, autoregressive evaluation, linear probes, report generation, tests, datasets, and outputs are not part of this standalone training repository.

## Reproducibility and scientific safeguards

- Checkpoints and early stopping must use patient-level validation, never training-fit monitoring.
- Event timestamps and censoring must be preserved; medication-related changes are observational associations, not causal effects.
- Cross-database evaluation should report both zero-shot and calibration-to-sealed-test results.
- HCMT-Core and HCMT-Full event sets should be reported separately for fair cross-database comparison.
- This repository contains no patient-level data.
